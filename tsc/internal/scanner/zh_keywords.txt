# ChineseTypeScript 关键字词表（唯一真源）
#
# 本文件是 ChineseTypeScript 汉语关键字译名的【唯一真源】。
# tsc/internal/scanner/zh_keywords_generated.go 由本文件生成，
# 生成器: chtstools/gen_zh_keywords.go     守卫: tsc/internal/scanner/zh_keywords_test.go
#
# 设计约束（与 Chinese++ 的 clang/include/clang/Basic/ChineseKeywords.def 同一套定则）：
#
#   1. 【只增不改】只"新增"拼写，绝不改 tsc/internal/scanner/scanner.go 里
#      textToKeyword 的任何英文条目。英文关键字的既有行为完全不变。
#
#   2. 【单一 token】每个中文拼写都映射到与英文原关键字【完全相同】的 ast.Kind。
#      因此词法分析之后的一切 —— parser / binder / checker / printer / ls ——
#      无需任何改动。
#
#   3. 【独立成表】中文别名【绝不】并入 textToKeyword / textToToken。
#      原因（有据，非推测）：scanner.go 的 tokenToText 是由 textToToken 倒排得到的
#      （L2255 `for text, kind := range textToToken { result[kind] = text }`），
#      而 Go 的 map 遍历顺序是随机的。若中文键混进去，tokenToText[KindIfKeyword]
#      会在 "if" 与 "如果" 之间【随机】取值，生成的 js 会不确定地含中文关键字，
#      即非法 JS。守卫 zh_keywords_test.go 会机器校核这一条。
#
#   4. 【译名唯一】译名不得重复。生成器与守卫都强制检查。
#
#   5. 【2–6 个汉字】译名不短于两个汉字、不多于六个汉字。
#      定则来自 Chinese++（用户 2026-09-23 明确：关键字至少两个汉字、最多 6 个汉字）。
#      理由：单字与用户标识符的冲突面太大，汉语术语本身也以双音节为主。
#      汉字数按【汉字】算，不按字节或总字符算。生成器与守卫都强制检查。
#
#   6. 【与 Chinese++ 同词】英文词相同者复用 Chinese++ 的既定译名
#      （如 if→如果、else→否则、class→类型、break→跳出、namespace→名域 …），
#      使同一份汉语词汇在两个产品线里含义一致。Chinese++ 的定例：
#      class 必须译作「类型」（不是「类」）。
#      在 TypeScript 里 class 与 type 并存，故 class→类型、type→类型别名。
#
# 格式：每行 `<英文关键字> <中文译名>`，`#` 起注释，空行忽略。
# 「英文关键字」必须与 scanner.go 的 textToKeyword 左侧完全一致。
