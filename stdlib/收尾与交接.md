## 一·五、本轮（256 轮）总账 —— 哪些做到了、哪些没做到

**做到（都有判据与提交为证）**

* ① 机制选定并**真编译验证**：接口增补（声明层）+ printer 限定成员位置改写（emit 层）；
* ② **单一真源**（一份 TSV）+ 两个生成器 + **唯一性/形态/数字等守卫**；
* ③ **端到端判据 11 项**（类型检查 → 负对照 → 英文并存 → 标准 JS 产物 → node 真跑 → 单一真源 → 每个译名有声明 → 二进制不旧 → 文档数字 → 夹具同名），
  外加**全量十项**（含上游 600 例零回归、Go 测试全集）；
* ④ **文档与发行包**：5 份许可/披露文件 + 包内 21 项点名自检 + **GitHub Release v0.1**（含资产）；
* 覆盖 **1759 个译名**（22.9%），**英文用法与诊断零回归**（每 ~100 条一次全量验证）。

**没做到（这才是目标保持 active 的原因）**

* **符号感知**（六·七）：没做 → 通用名词不敢翻（上百个高频名如 `code`/`color`/`content`/`count`/`event`/`file`/`input`/`link`/`page`/`path`/`pattern`/`user`…），
  且**用户自己同名成员仍会被误改**（已发作三次）；
* **自动加载**：没做 → 用户还得手写 `/// <reference>`，不是「装完就能用」；
* **命名空间嵌套 interface / 构造器静态成员**：不支持（前者试败，后者已取证不可行）；
* 覆盖率距 100% 仍远（22.9%），且**干净候选池已取尽**。

## 二、机制（三句话）

1. **声明层**：把上游 `lib.*.d.ts` 的成员**增补**一份汉语声明（`interface X { 汉语名(...): ... }`），
   接口名与类型**原样保留** → 英文用法零影响、类型检查通过、产物仍是标准 JS。
2. **emit 层**：printer 在**成员位置**把汉语名改写回英文规范名（`甲.追加(4)` → `甲.push(4)`），
   所以**产出的 JS 与英文写的一模一样**。全局名在任何引用位置改写。
3. **手工声明**：`tests-chts/zhstdlib/汉语标准库.d.ts` 放类型别名、全局 `声明变量` 与手写函数；
   其余全由生成器产出（`-成员.generated.d.ts`）。

## 三、怎么干活（照抄这几条命令）

```powershell
# 1) 加译名：编辑 stdlib/试点-数组与数学.tsv（一行一个：member<TAB>英文名<TAB>汉语名）
# 2) 重新生成（顺序不能反）
pwsh -File tools/gen_zhstdlib.ps1        # 唯一性守卫：一汉只能对一英
pwsh -File tools/gen_zhstdlib_lib.ps1    # 生成汉语声明（会打印接口块数与跳过项）
# 3) 重建编译器（守卫⑨会检查「二进制不比译名表旧」）
$env:GOPATH='E:\gopath'; $env:GOMODCACHE='E:\gopath\pkg\mod'; $env:GOCACHE='E:\gopath\build-cache'
pwsh -File tools/build_chtsc.ps1
# 4) 判据
pwsh -File tests-chts/judge_zhstdlib.ps1 -NoBuild
# 5) 每 ~100 条：全量十项 + 跑前跑后清构建缓存（否则 GOCACHE 会把磁盘撑爆）
pwsh -File tests-chts/run_all.ps1
Remove-Item E:\gopath\build-cache -Recurse -Force
# 6) 提交并推送（两端都推）
git add -A; git commit -m '...'; git push github main
```

## 四、护栏（这些判据会当场拦住你）

| 守卫 | 拦什么 |
|---|---|
| ① 类型检查 | 生成物语法坏了（例如对象字面量类型成员被截断 → TS1131） |
| ② 负对照 | 未声明的汉语成员必须报 TS2339 |
| ③ 英文+汉语并存 | 英文用法必须照旧可用 |
| ④⑤ 产物与真跑 | 产物必须是标准 JS，node 真跑输出正确 |
| ⑦ 单一真源 | 直接改生成物会被 `-Check` 抓出来 |
| ⑧ 每个译名都要有声明 | 「先翻译后补声明」/上游没有的名字 |
| ⑨ 二进制不比表旧 | 忘了重建编译器 |
| ⑩ 文档数字一致 | README 写 1723 就必须真是 1723 |
| ⑪ 夹具同名守卫 | 译名撞上我们夹具里用户自己的汉语成员（六·六 那个缺陷的早期预警） |

## 五、五类「生成器覆盖不到」的形态（别再往里加名）

1. **命名空间里嵌套的 interface**（`Intl.DateTimeFormat` 等）—— 试过，回退；
2. **构造器对象字面量的静态成员**——已**真编译取证**：增补不可行；
3. **对象字面量类型的多行成员**——✅ 已修（多行累积补上花括号平衡，六·十）；
4. **只在 `lib.webworker` 里的名字**——扫描时排除了 webworker/scripthost；
5. **含 ASCII/超 2~6 汉字的译名**——规则直接不收。

## 六、下一步（按性价比排序）

### 1) 符号感知（关键路径，必须先做）

**为什么**：现在的 emit 改写在**成员位置**一律替换。于是「用户自己也有一个叫 `描述` 的成员」时，
`甲.描述` 会被改写成 `甲.description` → **运行时才炸**。已**发作三次**（教程 `编号`、`demo_ident` 的
`描述` 与 `端口`）。也因此，`code`/`color`/`content`/`count`/`event`/`file`/`input`/`link`/`page`/
`path`/`pattern`/`user`… 这**上百个高频通用名词至今没敢翻**。

**怎么做**（`规模化方案.md` 六·七 有完整方案）：让 **checker** 在解析时把「这是标准库成员」的节点打上
标记（例如 emit 标志位 `EFChineseStdlib`），printer **只改写被标记的节点**，不再靠文本位置猜。
**必须同时新增一条判据**：用户自己定义了同名成员时，那一处**不能被改写**（现在这条是缺的）。
**两条失败教训**（六·七·附）：printer 侧「按文件作用域猜」无效；命名空间嵌套的改写会产生孤儿成员。

### 2) 自动加载（解锁真正的「装完就能用」）

现在汉语标准库要用户自己 `/// <reference>`。侦察结论：生成物由
`tsc/internal/bundled/embed_generated.go` + `libs_generated.go` 内嵌（由 `bundled/generate.go` 生成），
要同时进**默认 lib 集合**。是多步编译器改动，但路径已明。

### 3) 剩余译名

干净候选已取尽；剩下约 160 个**几乎全是通用名词**（见上，等符号感知）与**关键字噪声**
（`const`/`default`/`eval`/`for`/`from`/`function`/`return`/`static`/`throw`/`try`/`var`/`with`/`yield` —— **不要译**）。

## 七、没做 / 没验证的（诚实清单）

* **符号感知没做**（上面第六·1）——这是覆盖率的硬上限；
* **自动加载没做**，所以标准库汉化目前是「要手写一行 reference」的半成品形态；
* **命名空间嵌套 interface / 构造器静态成员** 不支持（前者试败，后者已取证不可行）；
* 发行包**只在 Windows 上验证**（win64），没在无开发环境的干净机器上装过；
* 判据全量十项**依赖本机环境**（Go、node、python、`E:\cts-base` 工作树）；`E:\cts-base` 若被改写历史弄坏，
  会以「Go VCS 盖章失败 exit 128」的形式**假报回归**（见 README §一的连带坑）。
