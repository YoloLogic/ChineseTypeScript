## 二、机制（三句话）

1. **声明层**：把上游 `lib.*.d.ts` 的成员**增补**一份汉语声明（`interface X { 汉语名(...): ... }`），
   接口名与类型**原样保留** → 英文用法零影响、类型检查通过、产物仍是标准 JS。
2. **emit 层**：printer 在**成员位置**把汉语名改写回英文规范名（`甲.追加(4)` → `甲.push(4)`），
   所以**产出的 JS 与英文写的一模一样**。全局名在任何引用位置改写。
3. **手工声明**：`tests-chts/zhstdlib/汉语标准库.d.ts` 放类型别名、全局 `声明变量` 与手写函数；
   其余全由生成器产出（`-成员.generated.d.ts`）。

## 五·六、质量抽查（例行流程，2026-10-10 固化）

**为什么需要**：机器守卫只查「唯一性 / 长度 / 名字存在」，查不出**语义错误**与**可读性**。

| 轮 | 问题 | 修正 |
|---|---|---|

| 49 | filter→滤镜（摄影术语） | → **筛选** |
| 49 | max→最大限制、min→最小限制（像「上限」） | → **取最大** / **取最小** |
| 50 | dir→书写方向（那是 CSS direction） | → **展开对象** |
| 50 | info→附加信息（拗口） | → **信息** |
| 50 | resolve→解析路径（那是 path.resolve） | → **兑现** |

| 52 | method→提交方法（本义就是「方法」） | → **方法** |

**抽查方法（可复用）**

1. **按英文后缀分组**统计中文结尾（Type/Size/Time/Index/Id 等），找「同一后缀多种结尾」；
2. **按接口分组打印**核心成员（Array/String/Number/Math、console/Promise/Map/Set、
   Date/RegExp/JSON/Error/事件、迭代器、URL/fetch），人眼过一遍顺不顺口；
3. 抽查时若发现**漏译**，先确认该名字在**被扫描的 lib** 里（不含 webworker/scripthost），再入表；
4. **反向查重**：同一英文名若有多行译名（`Group-Object e -CaseSensitive`），逐个看「两个名字是否真在不同接口/不同语义」——
   不同接口且语义不同可留（如 Array.filter=筛选 vs Canvas.filter=过滤），**同一属性两种叫法必须合并**；
5. 每次修正后必须重跑 judge_zhstdlib（唯一性守卫会拦撞车），并同步 `stdlib/README.md` 的「译名：**N / 7687**」（⑩ 会抓文档漂移）。

### 1) 符号感知（关键路径，必须先做）

**为什么**：现在的 emit 改写在**成员位置**一律替换。于是「用户自己也有一个叫 `描述` 的成员」时，
`甲.描述` 会被改写成 `甲.description` → **运行时才炸**。已**发作三次**（教程 `编号`、`demo_ident` 的

**怎么做**（`规模化方案.md` 六·七 有完整方案）：让 **checker** 在解析时把「这是标准库成员」的节点打上
标记（例如 emit 标志位 `EFChineseStdlib`），printer **只改写被标记的节点**，不再靠文本位置猜。
**必须同时新增一条判据**：用户自己定义了同名成员时，那一处**不能被改写**（现在这条是缺的）。
**两条失败教训**（六·七·附）：printer 侧「按文件作用域猜」无效；命名空间嵌套的改写会产生孤儿成员。
