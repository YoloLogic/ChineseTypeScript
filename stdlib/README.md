## 机制：已定 **① 编译器改写**（2026-10-08）

用户方案是**声明层**：复制英文标准库、改成汉字，并用别名让英文用法照旧可用。
但 TS 与 C++ 有一处根本差别 —— C++ 的标准库是**真实代码**（改名即改运行时），
TS 的标准库是**只有声明、没有实现**的 `.d.ts`（真正的 `push`/`length` 长在 JS 引擎里，我们改不动）。
所以只改声明，`甲.添加(3)` 会原样进产物 → 运行时 `添加 is not a function`。

因此运行时那一半选 **① 编译器改写**：汉语标准库名在 **emit 时自动打回英文规范名**
（`甲.添加` → `甲.push`、`数学.取整` → `Math.floor`）。产物是**标准 JS**、无运行时依赖、随处可跑。

**可行性证据（已核查，不是假设）**：
* `ast.Node` 带 `Symbol()` / `LocalSymbol()`（`tsc/internal/ast/ast.go:240`）——
  emit 时能知道一个标识符解析到了哪个符号；
* emitter 已挂 `EmitResolver`（`tsc/internal/compiler/emitter.go:120`、`emitHost.go:42`）——
  这是现成的「emit 期向 checker 提问」的扩展点。
